# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm start` — dev server at http://localhost:4200 (alias for `ng serve`, default `development` configuration).
- `npm run build` — production build into `dist/` (default `production` config; budgets: 500kB initial warn / 1MB error, 4kB / 8kB per component style).
- `npm run watch` — incremental dev build (`ng build --watch --configuration development`).
- `npm test` — Vitest via `ng test`. Run a single spec with `ng test --include='src/path/to/file.spec.ts'`.
- `npx ng generate component <name>` — scaffolding. Note: `angular.json` sets `skipTests: true` for all schematics, so no `.spec.ts` is generated by default.

## Environment / Secrets

`src/environments/environment.ts` is **gitignored** (see `.gitignore` line 45) but a placeholder version is checked in with `'TU_SUPABASE_URL'` / `'TU_SUPABASE_ANON_KEY'`. Replace those locally with real Supabase credentials before running. Never commit real keys back to this path.

The Supabase project must have the schema from `supabase-schema.sql` applied — it creates the `public.tasks` table, enables RLS, and installs four policies that scope every row to `auth.uid() = user_id`. The backend security model relies on RLS, not on client code, so do not bypass `user_id` filtering server-side.

## Architecture

Angular 21 **standalone-components** app (no `NgModule`s). Bootstrapping happens in `src/main.ts` via `bootstrapApplication(App, appConfig)`; `appConfig` (`src/app/app.config.ts`) is the single composition root and only registers `provideRouter(routes)` and `provideBrowserGlobalErrorListeners()`.

**Routing** (`src/app/app.routes.ts`): two routes — `/login` (public) and `/dashboard` (gated by `authGuard`). Anything else redirects to `/login`. The guard is a `CanActivateFn` that calls `AuthService.getUser()` and redirects on null. It awaits the Supabase call, so navigation to `/dashboard` is asynchronous.

**Supabase layer** is three services, all `providedIn: 'root'`:

- `SupabaseService` — owns the single `SupabaseClient` instance built from `environment`. Every other service must go through `supabaseService.client`; do not call `createClient` again elsewhere.
- `AuthService` — wraps auth calls and exposes a `user$: Observable<User | null>` backed by a `BehaviorSubject`. On construction it both fetches the current user and subscribes to `onAuthStateChange`, so the subject stays live for the app's lifetime.
- `TaskService` — CRUD against the `tasks` table. `createTask` injects `user_id` from `auth.getUser()` before insert (RLS will reject inserts where `user_id !== auth.uid()`). `updateTask` also stamps `updated_at` client-side.

**Domain model** (`Task`, `src/app/models/task.model.ts`) uses **Spanish enum values** that must match the DB CHECK constraints exactly:

- `priority`: `'alta' | 'media' | 'baja'`
- `status`: `'pendiente' | 'en_progreso' | 'completada'`

UI labels, filters, and column groupings throughout `DashboardComponent` are keyed on these strings — if you rename one, update the DB constraint, model, dashboard filters/groups, and any template references together.

**Dashboard** (`src/app/components/dashboard`) is the only authenticated screen. It owns task state locally (`tasks: Task[]`), and after every mutation calls `loadTasks()` to refetch rather than mutating the array in place. Filtering, search, kanban grouping by status, and stats are all derived via getters from that one array.

## Deployment

`vercel.json` rewrites every path to `/index.html` so the Angular router can handle deep links. The build output (`dist/`) is what Vercel serves — there is no server-side runtime, only the static SPA + Supabase as the backend.
